# OurWay audit — 18 Nov 2026

Branch `feature/audit-simplification` (based on `main` after PR #9). Nothing has been committed or deployed, and the production database has not been changed.

## 1. What already works (checked in the code and against the live database)

| Area | State |
|---|---|
| Admin auth | Server-side `requireAdmin()` on every page and action (`getUser` plus an `admin_users` row). RLS repeats the check. Safe `next` redirect. Logout clears the session. Admin pages send `noindex` and `no-store`. |
| Password recovery | Only admins get reset emails, and the site never reveals whether an email belongs to an admin (hashed server key). |
| Spam protection (PR #9) | **Verified live:** the public key gets `permission denied` on `submit_booking_request`, `submit_private_request` and `record_submission_email`. Only the server, using `SUPABASE_SECRET_KEY`, can create requests. Honeypot, fill timer, IP rate limit, idempotency and the 30-minute duplicate check all work. The key is never sent to the browser (`server-only`). |
| RLS | **Verified live with the public key:** bookings, notes, history and email log return `[]`. `private_requests` and `booking_overview` are denied. Inserting into `excursions` is blocked. |
| Booking capacity | Checked in the database with a row lock (`FOR UPDATE`), so two requests can't take the same last places. Confirming a request re-checks capacity. Capacity can't be lowered below places already held. Requests are always "pending" until an admin confirms them, and there are no payments. |
| Tailor-Made | Separate table, statuses, notes, history and admin section. Kept apart from bookings. |
| Uploads | Images only (JPEG/PNG/WebP/AVIF, no SVG), max 10 MB, admins only. |
| SEO lock | `noindex`, no sitemap until launch, `/api/` disallowed. Unchanged. |
| Tracking | No analytics, ad cookies or third-party scripts. Fonts are self-hosted. **No cookie banner needed.** |
| Dependencies | `npm audit --omit=dev`: 0 vulnerabilities. |
| Admin UX basics | Delete confirmations, an unsaved-changes warning, consistent toasts, search, filters and pagination are already there. |

## 3. Implemented in this branch

- **`supabase/migrations/0006_primary_category.sql`**: adds a nullable `excursions.primary_category` (`day_trip` / `two_day` / `package`) and an index. Existing data is untouched, and the file includes an undo line.
- **Admin excursion form**: a "Κύρια κατηγορία" select at the top. It is required to **publish** an excursion (events are exempt). Quick-publish from the list checks it too. The old free-text field is relabelled "Είδος δραστηριότητας" with a hint, and its data is kept. The admin list shows a category badge, or an amber "Χωρίς κατηγορία" badge when none is set.
- **Public Experiences page** (`ExperienceBrowser`): shows all experiences by default with nothing pre-selected. It has category chips (only categories that have experiences appear), an "All" chip, and a search box that ignores case and accents and also matches Latin spellings. Category and search combine, and there is a results count and a "no results → show all" state. Greek and English are both covered.
- The experience detail page shows the primary category as its eyebrow.
- Privacy policy rewritten in Greek and English. The "interim" notice stays.
- Admin label fix, dashboard shortcut removed, contact rate-limit cleanup.

## 5. Owner checklist

**Deploy order (important):** apply `0006_primary_category.sql` in the Supabase SQL Editor **before** merging and deploying. Otherwise saving an excursion in admin fails, because the column is missing. After deploying, assign a category to each excursion.

**Email (to make notifications work):**
1. Buy or choose the domain.
2. Resend → Domains → add the domain → add the SPF (TXT), DKIM (CNAME/TXT) and MX/return-path records it shows at the DNS host. Add DMARC (`_dmarc` TXT, start with `p=none`).
3. Wait until Resend shows "Verified".
4. Vercel env: `CONTACT_FROM_EMAIL="OurWay <hello@domain>"`, `CONTACT_EMAIL`, optionally `BOOKINGS_EMAIL`. Check that `RESEND_API_KEY` and `SUPABASE_SECRET_KEY` are set on Production. Redeploy.
5. Send a real booking request to an outside address and check the admin "email failures" panel.

The code already covers admin notification of new bookings and Tailor-Made requests, customer receipts, and customer confirmed / rejected / cancelled emails. **Delivery to customers will not work until step 4.**

**Legal (needs owner or lawyer):** controller identity, retention period, processor regions and transfer safeguards, booking terms and cancellation policy, consent wording (F7), safety information per excursion. Do not remove the "interim" notice until these are done.

**Supabase:** disable public sign-ups (F1). Consider leaked-password protection and a minimum password length matching the 12 characters the admin requires.

**Content:** unpublish or replace the "zagori" test experience (F2).
